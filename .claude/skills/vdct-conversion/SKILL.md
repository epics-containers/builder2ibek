# VDCT → msi Conversion

DLS support modules author their databases in **VisualDCT (VDCT)**. VDCT is a
Diamond extension that does **not exist in the vanilla EPICS 7 base that
epics-containers builds against**, so VDCT syntax has to be dealt with — but
which way depends on where the templates are going.

**Runtime patterns** (`ibek-runtime-streamdevice`) — conversion is **mandatory**,
and is what the rest of this skill covers. There is no build step: the templates
are expanded by msi when the IOC starts, so they must already be native `msi`
`include`/`substitute` directives.

**Support modules compiled into a generic IOC image** — conversion is
**optional** since `ibek-support/vdct` exists. That installs VisualDCT into the
developer stage and drops `%.vdb` → `%.template` rules into `$(EPICS_BASE)/cfg`,
so a module that keeps its `.vdb` sources builds straight from a pristine
upstream tag. Prefer it for this case: converting instead means maintaining a
pre-converted fork and re-making it on every upstream release (the `ecN` tag
pattern). See `ibek-support/vdct/README.md`.

Use with [ibek-concepts](../ibek-concepts/SKILL.md) when authoring the resulting
entity models.

## 1. Recognising VDCT source

Three markers, in order of usefulness:

| Marker | Meaning | Where |
|---|---|---|
| `template() {` + `#! InputMacro(NAME,...)` | **sub-template** — designed to be `expand()`-ed into a parent, never loaded standalone | child file |
| `expand("<child>.template", <instance>) { macro(N,"V") }` | the inclusion directive | parent file |
| `#!` lines (`#! Generated by VisualDCT`, `#! Record(...)`, `#! DBDSTART`) | VDCT layout/header junk | any VDCT file |

To find sub-templates in a module without cross-referencing parents:

```bash
grep -l '^template() {' <module>/<mod>App/Db/*
```

**Do not confuse `#!` with `#%`.** `#%` lines are DLS annotations (`#% autosave`,
`#% archiver`, `#% gui`, `#% macro`, `#% gdatag`) which are meaningful and must be
preserved. Only `#!` is VDCT junk.

### Source vs built output

- `<mod>App/Db/` — **VDCT source**. Convert this.
- `db/` — the **built** output; VDCT already ran at DLS build time, so
  `expand()` blocks appear only as inert `# expand(...)` / `# end(...)` comments
  around already-flattened records.

Extracting from `db/` "works" but bakes in the expansion (e.g. `currAmpOffsets.template`
in `db/` carries six inlined copies of `currAmpRange`). Prefer converting the
source so the runtime pattern keeps the include structure.

## 2. The tool: vdct2template

<https://github.com/epics-containers/vdct2template> (`pip install vdct2template`,
local checkout at `/workspaces/vdct2template`).

```bash
vdct2template --no-use-builder <folder>
```

What it does per parent `.vdb`:

1. Replaces each `expand("child.template", inst) { macro(RANGE,"6") }` block with
   ```
   substitute "_RANGE=6"

   include "child.template"
   ```
2. Rewrites the child in place, prefixing every substituted macro with `_`
   (`$(RANGE)` → `$(_RANGE)`).
3. Strips `#!` lines and `template() { }` blocks.

### Why the `_` prefix

msi will not apply a default when substituting a macro with its own name — it
sees the name as already defined. Renaming to `_RANGE` in the child sidesteps
this. It means **child templates are not independently loadable under their
original macro names** after conversion; only the parent's `include` path works.

### Options

- `--no-use-builder` — required when running on a copied folder, since the default
  looks for `<folder>/../../etc/builder.py`. With a real module tree you can omit
  it; it then warns if `builder.py` references a child template directly (an error,
  because the `_` prefix would break that reference).

## 3. The `.vdb`-only glob, and the rename workaround

`convert()` globs **`*.vdb` only**. Files carrying VDCT syntax under any other
extension are silently skipped.

Survey of the 30 DLS modules behind `ibek-runtime-streamdevice`:

| Category | Count | Handled today? |
|---|---|---|
| `.vdb` parents | 84 | yes |
| `.template` children named in an `expand()` | 4 | **yes** — see below |
| `.template` / `.db` VDCT-tagged, never referenced ("orphan flat") | 69 | **no** — skipped |
| non-`.vdb` parents containing `expand()` blocks | 0 | n/a |

**Every `expand()` reference in the corpus (18/18) names a `.template` file.**
That is the DLS convention: parents are `.vdb`, expandable children are `.template`.

### The referenced children already work

`Macros.template_path = filename.with_suffix(".template")` is a no-op on a file
that is already `.template`, so the tool reads the child, applies the `_` prefix,
strips VDCT junk and writes it back **in place**. Output is correct.

Two consequences: the rewrite is **not idempotent** (a second run would double the
prefix on newly-matched names), and it **mutates the source file**. Always work on
a copy.

### The fix: rename orphans, don't patch the tool

Renaming the skipped files to `.vdb` puts them in the glob. They land in
`convert()`'s flat branch, get `#!`/`template(){}` stripped, and are written back
out under their original `.template` name. No code change required.

**The exclusion rule is mandatory: never rename a file named inside an `expand()`
block.** The reference is a literal string; renaming `currAmpRange.template` to
`.vdb` leaves `expand("currAmpRange.template", ...)` pointing at a missing file and
`Macros.process()` dies on `read_text()`.

```bash
#!/bin/bash
# Rename VDCT-tagged sources to .vdb so vdct2template's *.vdb glob sees them.
# EXCLUDES files named inside an expand() block.
shopt -s nullglob
cd "$1" || exit 1
refs=$(grep -ho 'expand("[^"]*"' * 2>/dev/null | sed 's/expand("//;s/"//' | sort -u)
for f in *.template *.db; do
  [ -f "$f" ] || continue
  head -40 "$f" | grep -q '^#!\|^ *expand(\|^template() {' || continue
  if printf '%s\n' "$refs" | grep -qxF "$f"; then
    echo "SKIP (expand-referenced): $f"; continue
  fi
  echo "RENAME: $f -> ${f%.*}.vdb"
  mv "$f" "${f%.*}.vdb"
done
```

After the run the folder holds both `X.vdb` (renamed source) and `X.template`
(output). **Delete the `.vdb` files** — removing the module's VDCT dependency is the
whole point, and a leftover `.vdb` alongside its `.template` is a trap for the next
reader. Delete only where the `.template` was actually produced, so a file the tool
silently skipped does not lose its source:

```bash
for v in $WORK/*.vdb; do
  [ -f "${v%.vdb}.template" ] && rm "$v" || echo "KEEP (no .template produced): $v"
done
```

Expand-referenced children never had a `.vdb` (they were deliberately not renamed),
so nothing to clean up for those.

Caveat for true `.db` orphans (1 in the corpus: `ozone/ML9810B.db`): output lands
as `ML9810B.template`, so the installed filename changes. Fine for a runtime
pattern where we author the support YAML, but note the divergence from the DLS
module.

## 4. Workflow

`/dls_sw` is read-only and the tool mutates in place — always copy first.

```bash
MOD=/dls_sw/prod/R3.14.12.7/support/currAmp/1-45
WORK=$(mktemp -d)
cp $MOD/currAmpApp/Db/*.vdb $MOD/currAmpApp/Db/*.template $WORK/
chmod u+w $WORK/*

bash rename-vdct-orphans.sh $WORK      # section 3
vdct2template --no-use-builder $WORK

# drop the now-redundant VDCT sources
for v in $WORK/*.vdb; do
  [ -f "${v%.vdb}.template" ] && rm "$v" || echo "KEEP (no .template produced): $v"
done

# give annotation-only macros ($(name), $(gda_*)) an empty default -- see section 5.
# DO NOT SKIP: without this they look like required parameters. --dry-run to preview.
bash default-annotation-macros.sh $WORK

# verify: no VDCT syntax survives, no sources left behind
grep -l '^#!\|^ *expand(\|^template() {' $WORK/*.template   # expect no output
ls $WORK/*.vdb 2>/dev/null                                  # expect no output
```

`default-annotation-macros.sh` derives the set itself — a macro that survives once
comment lines are stripped is a real parameter and is left alone; the remainder are
annotation-only and get `=` appended. On currAmp 1-45 it reproduces the hand-picked
list exactly:

```
YMCS0009.template:       $(gda_bpm_desc) $(gda_bpm_name) $(gda_curr_name)
YMCS0012.template:       $(gda_bpm_desc) $(gda_bpm_name) $(gda_curr_name) $(name)
currAmpOffsets.template: $(gda_bpm_name)
currAmpSingle.template:  $(name)
```

Then copy the `.template` files into the pattern folder and author the
`*.ibek.support.yaml`.

### Worked example — currAmp 1-45 (validated)

| File | Role | Outcome |
|---|---|---|
| `currAmpOffsets.vdb` | parent, 6× `expand(currAmpRange)` | → `currAmpOffsets.template` with 6 `substitute`/`include` pairs |
| `currAmpADC.vdb` | parent, 6× `expand(currAmpRangeADC)` | → `currAmpADC.template` likewise |
| `currAmpRange.template` | sub-template | rewritten in place, `$(RANGE)` → `$(_RANGE)` |
| `currAmpRangeADC.template` | sub-template | rewritten in place |
| `currAmp_ai.template` | orphan flat | **needs rename** → `#!` stripped |
| `currAmp_ai_sim.template` | orphan flat | **needs rename** |
| `YMCS0009/0012.vdb`, `currAmpSingle.vdb`, `currAmp.vdb` | flat | `#!` stripped |

Then 9 annotation-only macros across 4 files get `=` defaults (listed above), and
`currAmp.template` is dropped — `Db/Makefile` never installs it, so it is build-time
only. Result: 6 entity models, 8 shipped templates, proved identical to the VDCT
build (section 6c).

## 5. Deriving entity models (`auto_*`)

XMLbuilder synthesises an `auto_<name>` AutoSubstitution class for every template
in a module's `db/`, whose ArgInfo is **exactly that template's macro set** — no
`pre_init`/`post_init`, no records beyond the template. An XML row `auto_xxxx`
just renders `xxxx.template`.

Modules therefore commonly ship far more templates than `etc/builder.py` declares
classes for. An extraction driven off `builder.py` alone (as the first
`ibek-runtime-streamdevice` pass was) silently misses them — currAmp's
`builder.py` declares 2 classes against 11 installed templates.

To reproduce `auto_*` in ibek:

- Name the entity model **after the template, dropping the `auto_` prefix**
  (`auto_currAmpOffsets` → model `currAmpOffsets`).
- Parameters = the template's macro set. Harvest from `#% macro, NAME, description`
  annotations where present, otherwise:
  ```bash
  grep -o '\$([A-Za-z_][A-Za-z0-9_]*)' <tmpl> | sort -u
  ```
- `databases:` — one entry, `file: <template>`, `args: {.*:}`.
- No `pre_init`/`post_init`.

**Exclude sub-templates.** A `template() {` file has no standalone existence — its
records already appear inside its parent, and after conversion its macros carry the
`_` prefix. Generating an `auto_*` model for one produces duplicate records.

So the generator rule is: **everything in `db/`, minus files matching `^template() {`.**

### Annotation-only macros → default them, don't parameterise them

Many macros appear **only inside `#%` annotation comments** — `$(name)` in a `#% gui`
line, `$(gda_bpm_name)`/`$(gda_curr_name)`/`$(gda_bpm_desc)` in `#% gdatag` lines.
They drive DLS EDM/GDA tooling that has no counterpart in epics-containers, but msi
still sees them as macros.

Do **not** give them entity-model parameters. Add an empty default in the template
instead — `default-annotation-macros.sh` (section 4) does this automatically:

```
$(name)          ->  $(name=)
$(gda_bpm_name)  ->  $(gda_bpm_name=)
```

This is already the DLS convention in these same files — `$(gda_name=)` and
`$(gda_desc=)` ship with empty defaults upstream. The script splits the two categories
with:

```bash
# macros reaching a record body (these become parameters)
grep -v '^\s*#' <tmpl> | grep -o '\$([A-Za-z_][A-Za-z0-9_]*[^)]*)' | sed 's/[=)].*//;s/\$(//' | sort -u
# every macro mentioned anywhere
grep -o '\$([A-Za-z_][A-Za-z0-9_]*[^)]*)' <tmpl> | sed 's/[=)].*//;s/\$(//' | sort -u
```

The difference is the annotation-only set. **Use `[^)]*` in the pattern** — a regex
requiring `)` straight after the name silently drops macros that already carry a
default, e.g. `$(SIGNAL=SR-DI-DCCT-01:SIGNAL)` in `currAmpOffsets.template`, which is
a genuine record-body parameter.

### When to KEEP `name` — it is a referenced id

Drop `name` by default, but **a class that is the target of an `Ident()` must keep
`name: type: id`**, or every entity pointing at it fails to resolve.

In builder.py the reference is the *second* argument of `Ident()`:

```python
Ident('Parent mks937b object', mks937b)          #  mks937b is an id target
```

So the test is "does this class appear as an `Ident` target anywhere":

```bash
uv run --no-project python find-id-targets.py <module>/etc/builder.py
# and anything referencing it from outside the module
grep -rln "modules\.<module> import" /dls_sw/prod/R3.14.12.7/support/*/*/etc/builder.py
```

It prints each target as `LOCAL` (this module's own class → keep `name: type: id`) or
`extern` (an asyn port or another module → says nothing about this module), then lists
the classes that may drop `name`.

**Do not hand-roll this with `grep | sed`.** The obvious
`grep -o 'Ident([^)]*)' | sed 's/.*, *//'` is greedy and returns only the *last* class
of a tuple — on mks937b it yields `mks937bPirg` and silently loses `mks937bImg`,
producing exactly the dangling-reference bug this section exists to prevent.

Three shapes come out of that grep, and only two mean "keep `name`":

| `Ident` target | Meaning | ibek mapping |
|---|---|---|
| `AsynIP`, `AsynSerial` | an asyn **port** from the asyn module, not an entity of this module | referrer gets a port param (`type: str` or an `object` on the asyn entity). Says nothing about this module's `name` |
| a class in **this** builder.py | sibling entity, parent/child relationship | **target keeps `name: type: id`**; referrer gets `type: object` |
| a **tuple** of classes | one arg accepting several entity types | **every class in the tuple keeps `name: type: id`** |

The tuple case is the trap — see [ibek-concepts](../ibek-concepts/SKILL.md). An
untyped `object` param may accept types you did not notice, so check all callers
before dropping an id.

#### Worked example — mks937b 2-97

```python
class mks937b(AutoSubstitution, AutoProtocol):        # <- id target
class mks937bImg(_mks937bImg_template):
        GCTLR = Ident('Parent mks937b object', mks937b)
class mks937bPirg(_mks937bPirg_template):
        GCTLR = Ident('Parent mks937b object', mks937b)
class mks937bCap(_mks937bCap_template):
        GCTLR = Ident('Parent mks937b object', mks937b)
class mks937bRelays(mks937bRelays_template):
        GAUGE = Ident('Parent mks937bPirg or mks937bImg object',
                      (mks937bImg, mks937bPirg))       # <- tuple
class mks937bGauge(AutoSubstitution):                  # no Ident anywhere
```

| Class | `name` | why |
|---|---|---|
| `mks937b` | **keep, `type: id`** | GCTLR target from three children |
| `mks937bImg`, `mks937bPirg` | **keep, `type: id`** | inside the `GAUGE` tuple |
| `mks937bCap` | drop | references others, never referenced |
| `mks937bRelays`, `mks937bFastRelay` | drop | referrers only |
| `mks937bGauge`, `mks937bHy8401`, `mks937bGaugeGroup`, `mks937bImgGroup` | drop | bare `AutoSubstitution`, no `Ident` |

The shipped `mks937b` pattern already keeps `name: type: id` correctly — but it ships
only that one model, so the `GCTLR`/`GAUGE` children are still missing (the same
`builder.py` blind spot from section 5). Adding them means `GCTLR: type: object`
pointing at the `mks937b` id.

Verify with the script:

```
$ find-id-targets.py mks937b/2-97/etc/builder.py
LOCAL  mks937b
LOCAL  mks937bImg
LOCAL  mks937bPirg
```

#### currAmp, for contrast

```
$ find-id-targets.py currAmp/1-45/etc/builder.py
no Ident() targets - every class may drop `name`
```

No `ArgInfo`, no `Ident`, and nothing imports it. `name` dropped everywhere and
defaulted to `$(name=)`.

#### Failure signature

Drop an id that is still referenced and validation fails with:

```
Value error, object XXX not found in [...]
```

If you see that, restore `name: type: id` on the entity named in the message.

**Caveat for `auto_*`:** a synthesised `auto_xxxx` has no class in builder.py at all,
so "builder.py shows no cross-reference" is trivially true and proves nothing. For
those, check whether an IOC XML row's `object`-typed attribute names the `auto_` row.

### Pristine-file rule no longer holds

`ibek-runtime-streamdevice`'s README says extracted `.template`/`.proto` files are
byte-for-byte copies of the DLS module. **VDCT conversion already breaks that**, and
adding `=` macro defaults breaks it further. For any VDCT-converted module the shipped
template is a derived artifact — record the source path and version in the support
YAML's provenance comment instead, and update the README's pristine claim to carve
these out.

## 6. Validation

Three levels. Do all three — the first two pass on output that is still semantically
wrong.

### a. Schema + parameter completeness

Build a scratch config dir holding the converted templates and an `ioc.yaml` that
instantiates **every** entity model, then:

```bash
uv run ibek runtime generate2 <config-dir> \
    --definitions <pattern>/<module>.ibek.support.yaml -o <out> --no-pvi
```

Silence means success. It writes `ioc.subst` + `st.cmd`; check the `.subst` columns
match the parameters you declared.

### b. msi expands with no undefined macros

```bash
MSI=/epics/epics-base/bin/linux-x86_64/msi
cd <config-dir> && $MSI -I. -S <out>/ioc.subst > expanded.db
grep -o '\$([A-Za-z_][^)]*)' expanded.db | sort -u    # expect no output
```

This is what catches a missed `=` default or an `include` target you forgot to ship.
Run msi from the config dir so `include "currAmpRange.template"` resolves.

### c. Equivalence against the original VDCT build — the one that matters

The DLS module's `db/` holds the VDCT-built output. Expand the converted template and
the DLS-built template with the same macros and compare canonical record/field sets.
`canon-db.py` (in this skill dir) normalises a `.db` into sorted `record → sorted
fields` blocks, so ordering and comment differences don't produce noise:

```bash
for side in dls new; do
  ( cd $side && $MSI -I. -M "P=TEST,RANGE=10,INP1=A1,..." $t.template ) > $t.$side.db
  uv run --no-project python canon-db.py $t.$side.db > $t.$side.canon
done
diff $t.dls.canon $t.new.canon      # expect no output
```

Pass empty values for the annotation-only macros you defaulted (`name=`,
`gda_bpm_name=`, ...) so both sides expand identically.

**currAmp 1-45 result:** all 6 templates identical — `currAmpOffsets` 42 records,
`currAmpADC` 51, `YMCS0009` 58, `YMCS0012` 55, `currAmpSingle` 3, `currAmp_ai` 1.
That is the proof the `substitute`/`include` rewrite reproduces the VDCT expansion.

### Running vdct2template from a checkout

`src/vdct2template/_version.py` is generated by setuptools_scm at build time, so a
bare `PYTHONPATH` run fails with `ModuleNotFoundError: vdct2template._version`. Copy
the package to a scratch dir and stub it:

```bash
cp -r /workspaces/vdct2template/src/vdct2template $SCRATCH/
echo '__version__ = "0.0.0-local"' > $SCRATCH/vdct2template/_version.py
PYTHONPATH=$SCRATCH uv run --with typer python -m vdct2template --no-use-builder $WORK
```

## 7. The alternative: build `.vdb` in the container (`ibek-support/vdct`)

For a support module compiled into a generic IOC image, prefer this over
conversion — the module then tracks upstream tags with no fork to re-make.
`ibek-support/vdct` installs VisualDCT into the developer stage and drops
`CONFIG_VDCT` + `RULES_VDCT` into `$(EPICS_BASE)/cfg`, which base includes for
every module via `RELEASE_TOPS`. Java is build-stage only, so the runtime image
is unchanged.

### Build ordering goes in `cfg/CONFIG*`, never `cfg/RULES*`

A `.vdb` names its dbd in a `#! DBD("...")` header, resolved **relative to the
`.vdb` file's directory**, and that dbd is usually generated by the module's own
`src`. Under `make -j` the `Db` directory can start flattening first, and
VisualDCT then prints `No DBD loaded! Exiting...` for every file.

The fix is `<dir>_DEPEND_DIRS`, and *where it is set* is the whole trick:

- base expands it while `RULES_DIRS` defines the inter-directory rules
  (`DEP_template2`), so it must already be set when that include is processed
- `RULES_DIRS` **never includes `RULES_FILE_TYPE`**, so `cfg/RULES*` is not read
  at App-Makefile level at all
- `cfg/CONFIG*` *is* read there, via the `configure/CONFIG` include at the top of
  the App Makefile

So `CONFIG_VDCT` sets it for every module at once, and no module needs patching.
Filter against `$(DIRS)` with a deferred (`=`) assignment, or a source directory
present on disk but excluded from the build gives
`No rule to make target 'src.install'`.

### VisualDCT exits 0 on failure

`GenerateFlatDatabase` returns success even when it gives up, so the build
surfaces only a secondary `mv: cannot stat '<x>.template'`. The `flatdb` wrapper
checks output was actually written. Expect this whenever debugging a vdb build.

### Validating the result

Same principle as §6c, but easier: diff the generated `.template` files against
a build of the *same module tag* made by the site's traditional VDCT harness
(`/dls_sw/prod/.../<module>/<tag>/db`). Normalise two cosmetic differences —

- the `#! Generated by VisualDCT` stamp, which carries the tool version
- absolute paths inside `# expand("...", name)` comments, which VisualDCT
  canonicalises against the build directory

— and anything remaining is real. Normalise exactly those two patterns and
nothing else, so any other difference still shows up:

```bash
norm() { sed -e 's|^#! Generated by VisualDCT.*|#! VDCT|' \
             -e 's|"/[^"]*/\([^/"]*\.vdb\)"|"\1"|' "$1"; }

for t in <ref-dir>/*.template; do
    n=$(basename "$t")
    diff <(norm "$t") <(norm "<generated-dir>/$n") > /dev/null \
        || echo "DIFFERS: $n"
done
```

The second expression rewrites `# expand("/abs/path/x.vdb", inst)` to
`# expand("x.vdb", inst)` on both sides. It deliberately touches only quoted
paths ending `.vdb`, so a real change to a record or field is never masked.

For dlsPLC 3-0-72 this reported no differences across all 83 templates.
